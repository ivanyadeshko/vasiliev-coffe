# Спецификация: анимированное TV-меню кофейни (4 экрана + админка)

Дата: 2026-08-31 · Статус: на утверждении у заказчика

## 1. Задача

Кофейня + фастфуд. Четыре телевизора 16:9 над кассой. На каждом — веб-страница
с **статичным меню** (название, описание, объём, цена) поверх **плавно
анимированного фона** (видеолупы, сгенерированные в Grok Imagine). Цены могут
меняться в любой момент через простую админку; анимация при этом не ломается,
потому что цены — это HTML-текст поверх видео, а не часть ролика.

Итог поставки: 4 ссылки (по одной на экран) + ссылка на админку.

## 2. Глубокий анализ и ключевые решения

| Проблема | Решение |
|---|---|
| Цены не должны «запекаться» в видео | Видео — только фон/витрина без текста (в промтах Grok жёсткое «no text»). Всё текстовое — HTML-слой поверх. |
| В «Мокко.docx» нет цен — цифры 40/250/350/450 это **объёмы (мл)** | Модель данных: у позиции поле `volume` (строка) и `prices` (1–2 числа, по числу объёмов). Цены заполняет владелец в админке; пустая цена отображается как «—». |
| Ролики Grok короткие (~6–15 с), виден стык лупа | Плеер из двух `<video>` с кроссфейдом ~1 с на стыке + промты «seamless loop, ends as it begins». На экран — плейлист из 2–3 роликов, ротация с кроссфейдом. |
| ТВ-браузеры капризные (кодеки, автоплей, память) | MP4 H.264 1080p ≤ 20 МБ, `autoplay muted loop playsinline`; постер-картинка как фолбэк, если видео не запустилось; автоперезагрузка страницы раз в сутки (04:00) против утечек памяти. |
| Меню должно обновляться само | Поллинг JSON раз в 60 с (настраивается). JSON крошечный (единицы КБ) + ETag/304 — нагрузка нулевая, можно чаще, чем просили (5–10 мин). |
| Экран не должен «падать» при проблемах с сетью | При ошибке поллинга показываем последние данные; последний удачный JSON кэшируется в localStorage — экран переживает даже перезагрузку без сети. |
| Нет БД | JSON-файлы на диске: `data/screen-{1..4}.json` + `data/settings.json`. Атомарная запись (tmp + rename), flock, автобэкап последних 10 версий. |
| Позиции «закончились» | Флаг `visible` у позиции (стоп-лист): скрыть, не удаляя. |
| Переполнение экрана при добавлении позиций | Мягкий лимит: админка предупреждает при превышении рекомендуемого числа позиций; фронт экрана имеет «компактную» типографическую ступень, включающуюся автоматически. |

## 3. Архитектура

Стек: **PHP ≥ 8.0 без фреймворков и без БД**, ванильные HTML/CSS/JS без
сборки. Разворачивается на любом shared-хостинге или `php -S` для разработки.

```
public/                     ← корень веб-сервера
  screen.php?id=1..4        ← экраны для ТВ (полноэкранные)
  api/menu.php?screen=N     ← GET: JSON меню экрана (+ ETag/304)
  api/save.php              ← POST: сохранение экрана (только админ-сессия)
  admin/login.php           ← вход по паролю
  admin/index.php           ← 4 карточки-экрана
  admin/screen.php?id=1..4  ← редактор позиций экрана
  assets/css|js|fonts       ← шрифты self-hosted (woff2), без внешних CDN
  assets/video/             ← ролики Grok (screen-1-a.mp4 …)
  assets/img/               ← постеры-фолбэки
data/                       ← ВНЕ webroot (или закрыт .htaccess)
  screen-1.json … screen-4.json
  settings.json             ← бренд, валюта, poll_seconds, хэш пароля админа
  backups/                  ← последние 10 версий каждого файла
```

### 3.1 Модель данных (`data/screen-N.json`)

```json
{
  "screen": 1,
  "title": "Горячие напитки",
  "updated_at": "2026-08-31T12:00:00+03:00",
  "media": { "videos": ["screen-1-a.mp4", "screen-1-b.mp4"], "poster": "screen-1.jpg" },
  "categories": [
    {
      "id": "classic", "title": "Классический кофе", "col": 1,
      "items": [
        { "id": "latte", "name": "Латте", "desc": "", "volume": "350/450 мл",
          "prices": [220, 260], "visible": true }
      ]
    }
  ]
}
```

- `prices`: массив из 1–2 чисел или `null` (→ «—» на экране). Два числа =
  цены за два объёма, порядок совпадает с `volume`.
- `col`: колонка раскладки (1|2) — категории привязаны к колонкам, чтобы
  добавление позиции не «перетасовывало» весь экран.
- `settings.json`: `{ "brand": "МОККО", "currency": "₽", "poll_seconds": 60,
  "reload_at": "04:00", "admin_password_hash": "…" }`.

### 3.2 API

- `GET api/menu.php?screen=N` → `200` JSON + `ETag` (md5 файла); при
  `If-None-Match` совпал → `304`. Публичный, `Cache-Control: no-store`.
- `POST api/save.php` → требует админ-сессию + CSRF-токен. Валидация на
  сервере: screen ∈ 1..4, структура полей, цены — числа|null, лимиты длин
  строк, ≤ 40 позиций на экран. Затем flock → бэкап → tmp+rename → `{ok}`.

### 3.3 Экран (frontend ТВ)

- Фиксированный «холст» 1920×1080, вписывается в окно через
  `transform: scale()` — одинаковая картинка на любом 16:9.
- Слои снизу вверх: видеофон (2×`<video>` кроссфейд-плеер) → тёмный
  градиент-скрим над зоной меню → HTML-меню → шапка (лого, заголовок).
- Поллинг раз в `poll_seconds`: изменился ETag → перерисовка. Изменённая цена:
  фейд 400 мс + однократная мягкая янтарная подсветка ~1.5 с. Новая позиция —
  фейд-ин, удалённая — плавное схлопывание. Раскладка при этом не прыгает:
  цены в колонке фиксированной ширины (табличные цифры).
- Автоперезагрузка страницы в `reload_at`.

### 3.4 Админка

Мобильная вёрстка (владелец правит с телефона). Вход по одному паролю
(hash в settings, PHP-сессия, пауза при неверном пароле). На страницу экрана —
таблица по категориям: имя, описание, объём, цена 1, цена 2, вкл/выкл
(стоп-лист), вверх/вниз, удалить; кнопка «добавить позицию» в категории;
переименование категории; одна кнопка «Сохранить» (POST всего экрана);
ссылка «посмотреть экран». Предупреждение при превышении рекомендуемого
числа позиций.

## 5. Дизайн и анимация

Полная дизайн-система — `docs/design-system.md`. Кратко: тёмный
эспрессо-фон (#120D0A), тёплый янтарный акцент (#E9A23B), кремовый текст
(#F4EAD9); заголовки Unbounded, текст/цены Manrope (табличные цифры),
точечные лидеры между названием и ценой. Композиция: слева ~⅓–45% —
«витрина» (там живёт анимация Grok), справа — меню на тёмном скриме.
Композиция задаётся уже в промтах Grok: объект слева, правая часть кадра
уходит в ровный тёмный фон. Анимация медленная и мягкая (пар, медленный
пролив молока, падающий лёд, сборка шаурмы в стиле рекламы McDonald's),
без резких движений и без текста в кадре. Промты — `docs/grok-prompts.md`.

## 6. Обработка ошибок

- Видео не запустилось за 4 с / ошибка → показываем постер (статичная
  картинка Grok), меню работает как обычно.
- Поллинг упал → тихий ретрай в следующем цикле, на экране последние данные.
- JSON повреждён на сервере → API отдаёт последний валидный бэкап и пишет в лог.
- Сохранение в админке: при ошибке валидации — понятное сообщение, данные
  формы не теряются.
