# Предзагрузка видео с лоадером и логи экранов

## Проблема

Жалоба: на ТВ (RAZZ, Яндекс Браузер) вместо видео «горит статичная картинка»,
иногда видео запускается. На других устройствах в том же Wi‑Fi — то же самое.
Картинка — постер `screen-N.jpg`, т.е. сработал `showPoster()` плеера.

Корень: `player.js` даёт каждому клипу 4 с на `canplaythrough`, а любая
неудача (таймаут, `onerror`, отказ `play()`) ставит `stopped = true` —
постер навсегда, до ночного reload в 04:00. Первые клипы весят 4,5–9,5 МБ
(до 7,4 Мбит/с), на слабом Wi‑Fi кафе (4 ТВ + гости на одном канале) за 4 с
не успевают. Каждый стык клипов — новая такая проверка.

## Решение

Экран сначала скачивает **все** клипы своих сцен, показывая брендовый
лоадер, хранит их в IndexedDB и играет из `blob:`‑URL. После первой
загрузки сеть на показ не влияет. Ошибки и ключевые события уходят на
бэкенд в JSONL-файлы для аудита.

Service Worker и Cache API не используются: прод работает по HTTP, а они
требуют secure context. IndexedDB работает и по HTTP.

## Компоненты

### 1. Манифест (`public/api/menu.php`)

В ответ добавляется `menu.media.files`: `{имя: {size, v}}` для всех
клипов из `media.scenes[*].videos` и `media.videos`, где `size` —
`filesize`, `v` — `filemtime` файла в `public/assets/video/`.
Отсутствующий файл в манифест не попадает. Имена берутся через `basename`.
ETag учитывает манифест (замена файла → новый ETag → экраны узнают).

### 2. `public/assets/js/media-cache.js` — `window.MokkoMediaCache`

`ensure(files, onProgress, onRetry) → Promise<{имя: blobUrl}>`

- Ключ в IndexedDB (`mokko-media`, store `clips`): `имя@v`.
- По каждому файлу: попытка из IndexedDB → иначе XHR `responseType:'blob'`
  с `onprogress` → запись в IndexedDB.
- Прогресс: `onProgress(loadedBytes, totalBytes)`, total — сумма `size`
  из манифеста; кэш-хиты засчитываются сразу.
- Сбой скачивания (сеть, HTTP ≠ 200, размер ≠ `size`): повтор бесконечно,
  паузы 5 → 15 → 30 → 60 с (далее 60). `onRetry(секунд, файл)` для UI.
  Уже скачанные файлы не перекачиваются.
- IndexedDB недоступна/ошибка записи — работаем из памяти (blob в
  переменной), событие `media.idb_fail` в лог один раз.
- После успешного `ensure` — уборка: удалить из store ключи, которых нет
  в текущем манифесте экрана (база своя на каждый origin; экраны 1–4 на
  разных ТВ, но на одном устройстве могут быть открыты разные экраны —
  поэтому ключи хранятся с префиксом `s<экран>/`, и уборка трогает только
  свой префикс).

### 3. `screen.js` → `setupMedia()`

- Нет видео в сценах → постер, как сейчас.
- Первый запуск: постер + лоадер (показывается, только если `ensure` не
  завершился за 400 мс), по готовности — лоадер гаснет, плеер стартует с
  blob-URL.
- Смена медиа при уже играющем видео: `ensure` фоном без лоадера, старый
  плеер играет; по готовности — `stop()` старого и старт нового.
  Если за время фоновой загрузки медиа сменились ещё раз — результат
  устаревшей загрузки выбрасывается (токен поколения).
- Старые blob-URL освобождаются (`URL.revokeObjectURL`) после остановки
  плеера, который их использовал.

### 4. `player.js` — страховка

- Таймаут `prepare` 4 → 10 с (blob локален, это запас для слабого железа).
- Ошибка/таймаут/отказ `play()` → лог + постер, но **не навсегда**:
  через 30 с `step()` пробует снова со следующего клипа.
- Остановленный плеер не трогает DOM (`catch`/таймеры проверяют `stopped`),
  чтобы не гасить видео нового плеера.
- `opts.onEvent(event, data)` — хук для логов (`player.error`,
  `player.play_rejected`, `player.retry`, `player.timeout`).

### 5. Лоадер (разметка в `screen.php`, стили в `screen.css`)

Центр видимой части витрины (левая зона, до скрима меню):

- Векторная (inline SVG) эмблема по мотивам `logo.jpg`: вид на чашку
  сверху + ручка, буква «М», три струйки пара.
- Внешнее кольцо чашки — прогресс-кольцо (`stroke-dashoffset` по %).
- Появление: чашка и «М» прорисовываются линией за 0,8 с.
- Пар: три струйки рисуются снизу вверх и тают, сдвиг фаз, цикл ~2,4 с.
- Кофе в чашке мягко «дышит» (opacity).
- Под эмблемой — «МОККО» (Unbounded 700, .1em) с пробегающим бликом
  `--accent → --accent-hi`, ниже подпись Manrope 20 px `--mut`:
  «Загружаем видео · 42 %».
- Ошибка сети: кольцо `--mut`, подпись «Нет связи · повтор через N с»
  с обратным отсчётом, пар замедляется.
- Фон — постер с медленным «наездом» (scale 1→1.06, 20 с, туда-обратно)
  под тёплым затемнением; без blur (дорого для ТВ‑GPU).
- Финал: кольцо замыкается, лоадер уходит в opacity с лёгким scale за
  0,6 с, видео проявляется.
- Анимации только `transform`/`opacity`/`stroke-dashoffset`, чистый CSS;
  `prefers-reduced-motion` — без анимаций.

### 6. Логи с фронта — `public/assets/js/log.js`, `window.MokkoLog`

- `MokkoLog.info|warn|error(event, data)`.
- Запись: `{ts, screen, sid, level, event, data}`; `sid` — случайный id
  загрузки страницы.
- Буфер в памяти + копия в `localStorage` (`mokko-log-<screen>`, до 200
  записей, старые вытесняются) — переживает офлайн и reload.
- Отправка: раз в 30 с, при `error` — сразу; пачка до 50 записей; при
  неудаче записи остаются в буфере.
- `window.onerror` и `unhandledrejection` → `js.error`.
- События: `boot`, `media.cache_hit`, `media.download_ok`,
  `media.download_fail`, `media.idb_fail`, `media.ready`, `player.*`,
  `js.error`, `heartbeat` (раз в 10 мин: state, clip, uptime).

### 7. Приём логов — `public/api/log.php` + `lib/logs.php`

- Только POST JSON `{entries:[...]}`; тело ≤ 32 КБ; ≤ 50 записей.
- Нормализация записи: `screen` 1..4 (иначе запись отброшена), `level`
  ∈ info/warn/error (иначе info), `event` — `[a-z0-9._-]`, ≤ 64,
  `data` — JSON ≤ 2 КБ после кодирования, строки ≤ 500 символов,
  `sid` ≤ 32, `ts` — строка ≤ 40.
- Сервер добавляет `received_at` (ISO 8601) и `ip` (`client_ip()`).
- Запись: `data/logs/screens-YYYY-MM-DD.jsonl`, `FILE_APPEND | LOCK_EX`.
- Лимит 20 МБ на дневной файл — сверх него записи не пишутся.
- Ретенция: при записи удаляются файлы старше 30 дней.
- Ответ `204`; невалидный запрос — `400`/`405`/`413`.
- Без авторизации (экраны не залогинены).
- `data/logs/` — в `.gitignore`, исключён из rsync в `deploy/deploy.sh`.

## Тестирование

- PHP (`tests/run.php`): `tests/api_log_test.php` — метод, размер, лимит
  записей, нормализация, запись в файл, лимит размера, ретенция;
  `tests/api_menu_test.php` — наличие `media.files` с size/v.
- JS — вручную в Chrome с троттлингом сети: первая загрузка с лоадером,
  повтор из IndexedDB без лоадера, обрыв сети посреди загрузки (повтор с
  отсчётом), смена медиа, логи в файле.

## Вне рамок

Пережатие видео до меньшего битрейта, HTTPS, просмотр логов в админке.
